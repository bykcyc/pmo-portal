# RDProject — фронтенд PMO-портала

**В этом каталоге живёт только фронт.** Бэкенд — `PMO/pmo-backend/` (FastAPI + собственный PostgreSQL).
Описание системы (топология, модули, проверки) — в корневом `ARCHITECTURE.md`.

> Историческая справка: каталог `backend/` (FastAPI + SQLAlchemy) и `docker-compose` с ним удалены
> 10.07.2026 — это была первая версия портала. Её документация (`ARCHITECTURE.md`, `TASKS.md`,
> `README.md`) из этого каталога тоже удалена; актуальное описание системы — в корневом
> `ARCHITECTURE.md`.

## Что здесь

```
frontend/          React 18 + Vite + TypeScript + Tailwind
  src/api/         по файлу на модуль портала; все запросы идут через client.ts (baseURL '/api')
  src/components/  ui/ — примитивы; tabs/ — 16 разделов проекта
  src/pages/       страницы (портфель, проект, мои задачи, календарь, настройки…)
  src/locales/     ru/en/lv — UTF-8 без BOM, CRLF, отступ 2
```
Весь стек (база + бэкенд + фронт) поднимается одной командой из корня PMO: `docker compose up -d`.

## Правила

1. **Фронт не знает о базе.** Любые данные — через `/api`. Контракт API менять только вместе с бэкендом
   и обязательной пересверкой эталонов (см. корневой `ARCHITECTURE.md`, раздел
   «Compatibility contract and verification»).
2. **Никаких строк в коде** — весь текст в `src/locales/*.json` (три языка сразу).
   Правку локалей делать скриптом (load → mutate → dump), сохраняя UTF-8 без BOM и CRLF.
   **Исключение — `src/content/**`**: это сам КОНТЕНТ (справка и новости), а не подписи
   интерфейса. Он переведён на все три языка, но живёт НЕ в локалях: 23 страницы прозы
   в `ru.json`/`lv.json`/`en.json` сделали бы эти файлы нередактируемыми, а плоские ключи не
   выражают структуру блоков (`p | ul | table | steps | shot`). Хранение — по каталогу на язык
   (`wiki/ru`, `wiki/lv`, `wiki/en`; так же `news/ru|lv|en`), русский — язык-источник и фолбэк.
   Хром вики и новостей (пункт меню, поиск, «Наверх», «Новое») — по-прежнему через i18n.
   Не «чините» это переносом текстов в локали.

   **Правило новостей.** Каждое изменение портала, заметное пользователю, сопровождается новостью
   в `src/content/news/**` — тем же изменением, что и сама правка, сразу на трёх языках, с датой
   и человеческим объяснением, что теперь можно. Чисто технические правки (рефакторинг, ускорение,
   тесты) новости не требуют. Паритет языков стережёт `news.test.ts`.
3. **Тёмная тема обязательна** для нового UI: каждому классу — парный `dark:`.
4. **Состояния загрузки, ошибки и пустоты** — во всех вкладках (`ui/skeleton`, `ui/feedback`).
5. **Права проверяет сервер**, фронт лишь прячет контролы: `useCanWrite()` из `contexts/ProjectPermission`.
6. `npm install` в `frontend/` на хосте **не запускать** — там смонтированы контейнерные (Alpine)
   `node_modules`, это сломает vite. Правка зависимостей — внутри контейнера.
7. После изменений: `npx tsc --noEmit`, `npm run test`, затем e2e и визуальные снимки из `C:\pw-runner`.

## Тесты

- Юнит: `docker exec pmo-frontend sh -lc "cd /app && npm run test"`
- E2E + визуальная регрессия: `cd C:\pw-runner && npx playwright test --workers=1`

**Спеки живут ЗДЕСЬ — в `frontend/e2e/`.** В `C:\pw-runner\e2e` лежит их зеркало, и правится
оно только скриптом:

```
python tools/e2e/sync_runner.py          # обновить зеркало перед прогоном
python tools/e2e/sync_runner.py --check  # проверить, что копия не разошлась
```

Руками в раннере спеки не правят. Так уже делали: копия ушла вперёд на два месяца, правки
жили вне гита, а в репозитории оставались тесты удалённых фич. Отдельный каталог нужен
потому, что `node_modules` фронта — контейнерные (Alpine), и браузеры Playwright туда не
ставятся; читать спеки прямо из репозитория раннер не может — Node ищет `@playwright/test`
рядом с файлом.

Что остаётся у раннера и в гит не попадает: `node_modules`, браузеры и эталонные снимки
визуальной регрессии в `pw-runner/e2e/__screenshots__` — они привязаны к данным конкретного
дева, как и эталоны API. Обновлять снимки только осознанно (`--update-snapshots`).

Календарь снимается с остановленными часами (`page.clock.setFixedTime` в `visual.spec.ts`):
он подсвечивает «сегодня», и без заморозки эталон краснел бы каждый день после съёмки.
